# RiE Elven Haven Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import RiE's elven holding (as the Elven Haven) and its elf building lines into the overhaul, renamed for
Anbennar, buildable only by elves, with game-start and decision conversion.

**Architecture:** A new generator `tools/build_rie_elves.py` (data `tools/data/rie_elves.py`) reuses the RiE copy
machinery of `build_rie_dwarves.py` and `rie_dwarf_rewrite.py`, made rules-module-aware. The holdings and governments
generators gain the new holding. Conversion logic is a generated effect; the game-start hook, decision and picker event
are hand-written.

**Tech Stack:** Python 3 (stdlib, `unittest`), CK3 script and localization.

**Spec:** `docs/superpowers/specs/2026-10-25-rie-elves-design.md`

## Global Constraints

- Script and loc files: UTF-8 with BOM, LF, tabs; loc header `l_english:`.
- Keys unprefixed as RiE has them (`elven_holding`, `elven_settlement_01..07`, `elven_agriculture_01`); new
  overhaul-only keys and files `aov_`-prefixed.
- Never edit `../anbennar-ck3-dev-master`; generated files are never edited by hand.
- Elf = `is_elvish_culture = yes` (character scope).
- Output file names start `aov_elven_` (not `aov_rie_`): the dwarf generator's orphan test owns `aov_rie_*` in
  `common/buildings`, `common/script_values` and `localization/english`.
- No Middle-earth names in player-facing text (the dwarf `FORBIDDEN_LORE` regex plus `Lórien|Lorien|Ulmo|Orom[eë]|
  Valinor|F[eë]anor|telain|Talan|Sindar|Noldor|Calaquendi|Mírdain|Mirdain|Onodrim`).
- Python commands: `python -I`.

## Review Focus

1. A converted castle keeps a vanilla building in a Haven slot: the swap must remove every level key of every
   building in the source holding's list that the Haven list lacks. Test: `test_conversion_removes_every_level`.
2. A human holder of a Haven sees elven buildings offered: every included block's `can_construct_potential` must
   check an elven holder. Test: `test_every_block_checks_an_elven_holder`.
3. RiE's hope gate turning into "only when the top liege is not an elf": the whole hope `OR` must go, not just its
   hope lines. Test: `test_settlement_has_no_top_liege_or`.
4. Dwarf outputs change when the shared code is parameterized. Test: the dwarf `FreshnessTests` pass unchanged.
5. A Haven barony under a tribal ruler fails the castle-level equivalence (tribal trigger variant). Test:
   `test_requirement_triggers_accept_haven_levels` covers both triggers.

  - `LEVEL_MAP = {"castle_01": 1, "castle_02": 3, "castle_03": 5, "castle_04": 7, "tribe_01": 1, "tribe_02": 2}`.

    `regimental_grounds` -> `elven_stables`).

    and never removed.
  - `NAMES`: key -> (name, description) for `elven_settlement_01..07`, every level of every line, and
    `building_type_<line>_01` per line (names from the spec Section 5 tables; type names in brackets there);
    `HOLDING_LOC`: the holding's keys (`elven_holding`, `local_holding_type_elven_holding`,
    `local_holding_type_capitalized_elven_holding`, `game_concept_elven_holding(_desc)`).
