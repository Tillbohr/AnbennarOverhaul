# Map Graphics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port Realms in Exile's map look (mountain/rock textures, lighting, colour grading, skybox, snowfall, fog of war, water settings and map shaders) into the Overhaul through one regenerable generator.

**Architecture:** `tools/build_map_graphics.py` reads the installed RiE, Anbennar and the game, and writes every output into this mod; `tools/data/map_graphics.py` holds the tuned tables. Pure functions per part (materials, shaders, environment, grading) are unit-tested on fixtures and, where installed, on the real files; `main()` writes everything. Outputs are committed, with `gfx/map/` art through Git LFS.

**Tech Stack:** Python 3 standard library only (no PIL/numpy), `unittest`, CK3 1.19 `.settings`/`.txt`/shader text files, DDS headers, ck3-tiger via `tools/validate.py`.

**Spec:** `docs/superpowers/specs/2026-10-13-map-graphics-design.md`

## Global Constraints

- Base mod `../anbennar-ck3-dev-master` and RiE are read-only; outputs go only into this mod.
- RiE root default `C:/Program Files (x86)/Steam/steamapps/workshop/content/1158310/2291024373` (`--rie PATH`); Anbennar `../anbennar-ck3-dev-master` (`--anbennar`); game root `C:/Program Files (x86)/Steam/steamapps/common/Crusader Kings III` (`--game`; it holds `game/`, `jomini/`, `clausewitz/`).
- Without RiE installed the generator exits with an error naming the missing path and writes nothing.
- Copied files are byte-for-byte; generated text files (`materials.settings`, `posteffect_volumes.txt`, `snow.settings`, `SKYX_skybox.txt`) keep the source's BOM/line endings and start with `# Anbennar Overhaul: generated by tools/build_map_graphics.py ...` lines; changed lines carry `# Anbennar Overhaul`.
- Every terrain texture copied for a material is 1024×1024 DXT5.
- Never copied from RiE: `court_scene.shader`, `lotr_event_shaders.shader`, `jomini/portrait*`, `jomini/texture_decals_base.fxh`, `gh_portrait_*`; `bordercolor.fxh`, `gh_camera_utils.fxh`, `dynamic_masks.fxh` stay Anbennar's.
- Python runs with `-I`; tests via `python -I -m unittest discover -s tools/tests`; `python -I tools/validate.py` must end `fatal: 0, error: 0, warning: 0`.
- Commits carry no attribution lines.

## Review Focus

- RiE updated with a renamed material/texture or include → the generator must stop with a message naming it, never write a half set (test: mapping to a missing RiE id raises `GeneratorError`; `main` writes only after every part built).
- A shader include that resolves nowhere, or a root that pulls an excluded portrait/court file → stop, naming the chain (test in Task 2).
- `snow.settings` left pointing at RiE's texture index 54 → snow drawn with the wrong Anbennar material (test in Task 3).
- Grading boxes in the wrong place (y flip, margin) or for regions meant to stay ungraded (test in Task 4).
- Running the generator twice, or after an Anbennar update, must give identical files (freshness test in Task 5).
