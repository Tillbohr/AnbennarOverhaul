# Raised Dwarven Mountains and Gates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise Anbennar's dwarven mountains to about Erebor's height by regenerating its height data, and place RiE's Erebor gate where dwarven mountains meet normal land.

**Architecture:** Two new stdlib modules: `tools/heightpack.py` (PNG I/O re-export and the packed-heightmap codec) and `tools/dwarven_mountains.py` (province analysis, raising rule, gate sites). `tools/build_map_graphics.py` gains `build_heightmap(roots)` in `build_all`, which writes Anbennar's four height files as whole-file overrides plus a gate map-object file and the copied gate model. All values live in `tools/data/map_graphics.py`.

**Tech Stack:** Python 3 standard library only (`zlib`, `struct`, `array`), `unittest`; CK3 1.19 map data (`heightmap.png`, `packed_heightmap.png`, `indirection_heightmap.png`, `heightmap.heightmap`, `provinces.png`, `definition.csv`, `default.map`, province terrain), map-object `.txt`, Git LFS.

**Spec:** `docs/superpowers/specs/2026-10-13-map-graphics-design.md`, section "Addendum (2026-10-13): Raised dwarven mountains and gates".

## Global Constraints

- Base mod, RiE and the game are read-only; outputs go only into this mod (`map_data/` overrides are this mod's files).
- Standard library only; `python -I`; tests `python -I -m unittest discover -s tools/tests`; `python -I tools/validate.py` ends `fatal: 0, error: 0, warning: 0`.
- Image orientation: every map image is stored top row = north in the PNG, but the packed format's coordinates run bottom-up (row 0 = south). Code works in map coordinates (x east, y north from 0 at the south edge); converting to/from PNG rows happens only in the readers/writers.
- Values (exact): `DWARVEN_TERRAINS = ("dwarven_hold_surface", "dwarven_hold", "cavern", "dwarven_road")`, `GATE_EXCLUDE_REGIONS = ("e_dragon_coast", "e_harpylen")`, `LIFT_PEAK = 50000`, `LIFT_MAX = 1.8`, `LIFT_GROUND_RING = 24`, `SOFT_CEILING = 60000`, `GATE_PAD = 2`, `GATE_RISE = 14000`, `GATE_RISE_DIST = 6`, `FADE_PX = 12`, `GATE_INSET = 3`, `GATE_SCALE = 0.7`, `GATE_YAW_OFFSET = 0.0`, `PACK_TOLERANCE = 257`.
- Generated text files keep the generated header (`# Anbennar Overhaul: generated by tools/build_map_graphics.py ...`); `heightmap.heightmap` keeps Anbennar's BOM/line endings.
- The generator builds everything before writing; any missing input raises `GeneratorError` naming it.
- Commits carry no attribution lines.

## Review Focus

- Repacking an unchanged heightmap must give back every block's heights exactly (copied tiles), or the whole map shifts (test in Task 1).
- A block next to a changed block shares its edge pixel: it must be repacked too, or seams appear (test in Task 1/3: `changed_blocks` covers the 33-pixel footprint).
- Orientation: one flipped axis puts the raise in the wrong place (tests in Tasks 1 and 2 check known provinces by map coordinates, e.g. Rubyhold near x 954, y 2451).
- Values over 65,535 or below the original outside gate pads (test in Task 3).
- Gates in excluded regions or facing inward (test in Task 4).

### Task 1: PNG I/O and the packed-heightmap codec

**Files:** Create `tools/pngio.py`, `tools/heightpack.py`, `tools/tests/test_heightpack.py`

**Interfaces (produces):**
- `pngio.read_png(data: bytes) -> Image` (`Image` = namedtuple `width, height, bit_depth, color_type, pixels: bytes` in PNG row order; filters 0-4, non-interlaced, color types 0/2/6, depths 8/16); `pngio.write_png(img: Image) -> bytes` (filter 0 rows, `zlib` level 6).
- `heightpack.Grid` — `width, height, values: array('H')` in map coordinates (`values[y * width + x]`, y = 0 south); `Grid.from_png(img)`, `Grid.to_png() -> Image` (16-bit grey).
- `heightpack.Settings` — parsed `heightmap.heightmap` (`tile_size`, `original_size`, `level_offsets: list[tuple[int, int]]`, `max_compress_level`, `empty_tile_offset`, raw text); `parse_settings(text) -> Settings`; `settings_text(s: Settings, level_offsets, empty_tile_offset) -> str` (only those two keys change).
- `heightpack.Block` — `step: int, level: int, tile: list[int]` (`(32 // step + 1) ** 2` values, row-major, y up).
- `heightpack.unpack(indirection: Image, packed: Grid, s: Settings) -> dict[tuple[int, int], Block]` (block key `(bx, by)`, by from the south; indirection pixel = `(column, row, step, level)`; tile origin `(column * size, level_offsets[level][1] + row * size)` in packed map coordinates).
- `heightpack.sample(grid: Grid, bx, by, step) -> list[int]` (heights at `(bx*32 + i*step, by*32 + j*step)`, clamped to the grid edge).
- `heightpack.choose_level(grid, bx, by, tolerance) -> int` (coarsest level whose tile, bilinearly interpolated back to 33×33, matches the grid within `tolerance`; level 0 always qualifies).
- `heightpack.changed_blocks(old: Grid, new: Grid) -> set` (blocks whose 33×33 footprint `[bx*32, bx*32+32] × [by*32, by*32+32]` has any changed value).
- `heightpack.pack(blocks: dict, packed_width: int, s: Settings) -> tuple[Grid, Image, list, tuple]` (returns packed grid, indirection RGBA image, `level_offsets`, `empty_tile_offset`); per level, blocks in `(by, bx)` order fill rows of `min(256, packed_width // size)` tiles; level bands stacked bottom-up from y = 0 with no overlap; the empty tile (Anbennar's level-4 tile at `empty_tile_offset`) is placed as the last level-4 tile.

- [ ] **Step 1: Failing tests:** `test_png_round_trip` (8-bit RGB, 8-bit RGBA, 16-bit grey, each filter type in a hand-made PNG fixture decodes correctly; `write_png` → `read_png` identical); `test_settings_round_trip` (Anbennar-style text: `settings_text` with the same offsets returns the input; new offsets change only `level_offsets`); `test_unpack_fixture` (a hand-built 2×1-block map with one level-0 and one level-1 block); `test_pack_unpack_round_trip` (pack → unpack gives the same blocks; bands don't overlap; each tile lies inside its band); `test_changed_blocks_include_neighbours` (changing pixel `(32, 5)` marks blocks `(0, 0)` and `(1, 0)`); real-data (`@skipUnless` Anbennar present, one shared decode per class): unpacking Anbennar's files and repacking all blocks unchanged → unpack again gives identical tiles for all 32,768 blocks; a block known to be level 4 stays level 4.
- [ ] **Step 2: Run** `python -I -m unittest discover -s tools/tests -p test_heightpack.py` → FAIL (modules missing).
- [ ] **Step 3: Implement.** Keep the probe's findings: indirection RGBA channels are (column, row, step, level); tile size `32 // step + 1`; all coordinates bottom-up.

### Task 3: Raising rule

**Files:** Modify `tools/dwarven_mountains.py`, `tools/tests/test_dwarven_mountains.py`

**Interfaces:**
- Consumes: Task 2's functions, `heightpack.Grid`, data constants.
- Produces: `soft_ceiling(v: float) -> int` (identity up to `SOFT_CEILING`; above it `60000 + 5535 * (1 - exp(-(v - 60000) / 5535))`, rounded, ≤ 65535); `range_ground(grid, pm, rng, dwarven, water) -> int` (median height of non-dwarven, non-water pixels within `LIFT_GROUND_RING` px of the range); `lift_factor(peak, ground) -> float` (`clamp((LIFT_PEAK - ground) / (peak - ground), 1, LIFT_MAX)`, 1 when `peak <= ground`; `peak` = the range's highest height); `raise_heights(grid, pm, dwarven, water, impassable, sites) -> tuple[Grid, dict]` (new grid plus a report: per range ground, peak before/after, factor; per site pad height and rise achieved). Order: range lift inside dwarven pixels (never lower, soft ceiling); gate pads (radius `GATE_PAD`, set to the normal-side border pixel's height) and cliffs (pixels within `GATE_RISE_DIST` of the pad on the inward side raised to at least `pad + GATE_RISE`, soft ceiling); fade (every change outside dwarven pixels scaled by `1 - d / FADE_PX`, d = distance in px to the nearest dwarven or cliff pixel, zero beyond).

- [ ] **Step 1: Failing tests:** `soft_ceiling` (60000 → 60000, monotone, < 65536 for 1e6); `lift_factor` (ground 10000, peak 20000 → 4.0 capped to 1.8; ground 15517, peak 40982 → 1.3535; peak above 50000 → 1); fixture grid with one range: heights inside raised by the factor, nothing outside the fade changed, nothing lowered except pad pixels, max ≤ 65535; gate fixture: pad flat, cliff ≥ pad + 14000 within 6 px inward; real-data (`@skipUnless`, shared build): every range's peak ≥ 50000 or factor == 1.8 or factor == 1, Rubyhold's range factor between 1.3 and 1.4 and its peak ≈ 50000, unchanged pixels farther than `FADE_PX` from any dwarven/cliff pixel.
- [ ] **Step 2: Run** → FAIL.
- [ ] **Step 3: Implement.** Restrict work to each range's bounding box grown by `max(LIFT_GROUND_RING, FADE_PX, GATE_RISE_DIST) + 2` px; distances by a bounded multi-source BFS (Euclidean-approximating 8-neighbour is fine).
- [ ] **Step 4: Run** → PASS; full suite OK.
- [ ] **Step 5: Commit** `"Heights: raise dwarven ranges and shape gate cliffs"`.
