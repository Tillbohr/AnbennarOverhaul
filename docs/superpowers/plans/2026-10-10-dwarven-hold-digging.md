# Dwarven Hold Digging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The 9 EU4 Anbennar holds on the CK3 map become a `dwarven_hold_holding` with a 10-level primary building that dwarves raise through repeated *Delving Campaign* activities (4 phases, EU4-style events), ruined by non-dwarf conquest and restored by decision.

**Architecture:** Balance and hold data live in `tools/data/holds.py`. A generator (`tools/build_holds.py`) writes the level buildings (assets copied from Anbennar's castles), the game-start conversion effect, the script values and loc. The existing holdings generator gains a new-holding mechanism, and a new governments generator adds the holding to `valid_holdings`. Hand-written `aov_hold_*` script holds the activity, events, decision, on_actions and modifiers. The ruined picture reuses the monument-painting path in the county view.

**Tech Stack:** CK3 1.19.0.6 script, ck3-tiger (`python -I tools/validate.py`), Python `unittest` in `tools/tests/`.

**Spec:** `docs/superpowers/specs/2026-10-10-dwarven-hold-digging-design.md`

## Global Constraints

- Base Anbennar (`../anbennar-ck3-dev-master`) is never edited. Script/loc: UTF-8 BOM + LF + tabs; Python/Markdown: no BOM, LF, written with `write_bytes`.
- New files `aov_`-prefixed; keys unprefixed where the spec names them (`dwarven_hold_holding`, `dwarven_hold_01`..`_10`, `deep_mine_01..03`, `runeforge_01..03`, `hall_of_the_ancestors_01..03`, `activity_hold_dig`), `aov_` elsewhere.
- Dwarf test everywhere: Anbennar's character trigger `is_dwarvish_culture = yes` (culture has `heritage_dwarven`).
- The 9 holds and their start state are exactly the spec's table; Khugdihr (`b_aghatehargun`) is the only ruined hold.
- Dig target for the next level = 50 × next level; campaign cost = 50 × current level gold (+100 Generous / +250 Lavish); campaign base = (20 + stewardship/2 + learning/4 + 5·diligent + 5·architect − 5·lazy) × pace (0.75/1/1.35) × investment (1/1.25/1.5).
- Phase lengths: Survey 3, Excavation 12, Shoring 6, Breakthrough 1 months, set with `progress_activity_phase_after` in each phase's `on_phase_active`.
- Ruin: county modifier `aov_ruined_hold` (`tax_mult` −0.5, `development_growth_factor` −0.5, `levy_size` −0.5). Restore: 300 gold, 200 prestige, 5 years.
- Generated files carry `# Anbennar Overhaul: generated by tools/<script>.py ...; do not edit by hand.`

## Review Focus

1. A hold changes hands among dwarves mid-campaign or by inheritance: progress stays on the hold; only a non-dwarf **conquest** ruins it. Inheritance or a grant to a non-dwarf must not ruin. *(Task 5 test `test_ruin_requires_conquest_and_non_dwarf`.)*
2. A ruler with two eligible holds: the campaign location must be one of their holds, and progress goes to the hold where the campaign ran. *(Task 6 test `test_progress_targets_activity_location`.)*
3. A campaign's progress overshoots the target: the surplus carries over and the level rises by exactly one. Level 10 is final, with no campaign possible. *(Task 6 test `test_level_up_carries_surplus_and_caps_at_ten`.)*
4. Restoration interrupted by losing the hold to a non-dwarf: it is cancelled. To a dwarf: it finishes for the new holder. *(Task 5 test `test_restoration_follows_dwarven_holder`.)*
5. A hold's barony with a Dwarovar monument (Seghdihr, Verkal Gulan, Hehodovar, Gor Ozumbrog, Khugdihr): converting the holding type must keep the special building, and the monument painting wins over the ruined picture. *(Task 4 test `test_conversion_keeps_special_buildings`, Task 8 test `test_monument_painting_before_ruined_entry`.)*

### Task 6: The Delving Campaign activity

**Files:**
- Create: `common/activities/activity_types/aov_hold_dig.txt`, `common/on_action/aov_hold_dig_on_actions.txt`, `events/aov_hold_dig_events.txt` (`namespace = aov_hold_dig`, events 100 and 101), `localization/english/aov_hold_dig_l_english.yml`, `tools/tests/test_hold_dig_activity.py`
- Modify: `common/scripted_effects/aov_hold_effects.txt`

**Interfaces:**
- Consumes: Task 2 values, Task 4 triggers, Task 5 `aov_hold_ruin_effect`.
- Produces:
  - Activity `activity_hold_dig`. Model the structure on vanilla `common/activities/activity_types/coronation.txt` (multiple predefined phases) and LotR's `lotr_mining.txt` (phase length via `progress_activity_phase_after`).
    - `is_shown`: `is_dwarvish_culture = yes`, landed, holds any hold.
    - `can_start`: not at war; any held province `aov_can_dig_at` (with `scope:digger = root`); gold ≥ that hold's `aov_dig_campaign_cost`.
    - `is_location_valid`: `aov_can_dig_at`, holder = host. `province_filter = domain`.
    - No guests (`max_guests = 0`, `allow_zero_guest_invites = yes`).
    - Options:
      - `aov_dig_pace`: careful / steady / reckless, with the `PACE` factors;
      - `aov_dig_investment`: none / generous / lavish, with `INVESTMENT` cost and factor.
    - Cost: `aov_dig_campaign_cost` + the investment gold.
    - `is_valid`: host alive, `aov_hold_is_working` at the location, host still holds it, the location not occupied and not under siege. **War does not invalidate** a running campaign.
    - AI: `ai_will_do` 0 when gold < 2 × cost; weights stewardship, `diligent`, `greedy`; `ai_check_interval = 12`.
  - Phases `aov_dig_survey` (order 1), `aov_dig_excavation` (2), `aov_dig_shoring` (3), `aov_dig_breakthrough` (4), all `is_predefined = yes`.
